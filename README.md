# TG WS Proxy (personal)

Локальный прокси для Telegram на Android 16 (API 36; работает с Android 8.0+).
Приложение слушает `127.0.0.1:1443` как обычный MTProto-прокси. Telegram подключается к нему,
а оно открывает WebSocket (`wss://kws{N}.web.telegram.org/apiws`) к нужному дата-центру
и гонит через него переупакованный поток. Если WebSocket недоступен, идёт обычный TCP на DC.
Содержимое сообщений не расшифровывается: оно остаётся зашифрованным end-to-end.

Логика повторяет Flowseal/tg-ws-proxy (MIT).

## Сборка

Нужны Android Studio (свежая, с поддержкой AGP 9.5) или JDK 17+ и Android SDK Platform 36.

    ./gradlew assembleDebug
    # APK: app/build/outputs/apk/debug/app-debug.apk

Либо откройте папку в Android Studio и нажмите Run. Первая сборка скачает Gradle 9.6.0 и AGP 9.5.0.
Release-сборка подписана debug-ключом, чтобы ставилась без своего keystore.

### Сборка на GitHub без установки чего-либо

В проекте есть `.github/workflows/build-apk.yml`. Создайте репозиторий на GitHub, залейте туда содержимое
папки (`git init && git add . && git commit -m init && git push`), откройте вкладку Actions: после
завершения job «Build APK» APK лежит в артефакте `tg-ws-proxy-apk`.
Можно запустить и вручную: Actions → Build APK → Run workflow.

## Использование

1. Запустите приложение, нажмите «Запустить».
2. Нажмите «Добавить прокси в Telegram» и подтвердите добавление в Telegram.
3. Разрешите работу в фоне («Разрешить работу в фоне»). На Xiaomi, Huawei, Samsung и др.
   нужно ещё отключить ограничения батареи и разрешить автозапуск в системных настройках.

## Автозапуск

В разделе «Автозапуск» два переключателя, они применяются сразу, перезапуск прокси не нужен:

- «Запускать при включении телефона» запускает прокси после загрузки системы и после обновления
  приложения (обновление убивает процесс). Сервис имеет тип `specialUse`, его Android 15+ разрешает
  стартовать из BOOT_COMPLETED (запрет там только для camera, dataSync, mediaPlayback,
  mediaProjection, phoneCall и microphone).
- «Запускать при открытии приложения» стартует прокси при каждом новом запуске приложения, если он остановлен.

Под переключателями показано, снято ли ограничение батареи. На Xiaomi, Huawei, Samsung и подобных
автозапуск надо дополнительно разрешить в системных настройках, иначе система блокирует старт при включении.
Если вы остановили прокси кнопкой, после следующей перезагрузки он снова запустится, пока переключатель включён.

Секрет создаётся один раз при первом запуске и не меняется, пока вы не сотрёте данные приложения.
Ссылка вида `tg://proxy?server=127.0.0.1&port=1443&secret=dd...` показана на экране.

## Настройки

- Порт: 1024–65535, по умолчанию 1443.
- IP для WebSocket по DC: `2:149.154.167.220, 4:149.154.167.220`. DC, которого нет в списке,
  идёт сразу по TCP. Значения взяты из upstream, при изменении у Telegram их придётся поправить.
- Пул: сколько готовых WebSocket держать на каждый DC (0 отключает пул).

## Устройство

    core/        чистая Java без Android: MTProto obfuscated2, WebSocket-клиент, пул, прокси-сервер
    ProxyService foreground-сервис (тип specialUse), держит CPU wake lock, пока прокси работает
    MainActivity экран: статус, ссылка, настройки, статистика, журнал
    dev-tests/   проверка ядра на обычной JVM против поддельных серверов Telegram

Проверка ядра на ПК (нужны java и python3 с пакетом `cryptography`):

    mkdir out && javac -d out app/src/main/java/dev/personal/tgws/core/*.java dev-tests/CliMain.java
    python3 dev-tests/test_proxy.py out
